# Fagoo communication engine

Internal service imported from Wabotia 0.10.0, source commit `0ac0837`. Original MIT license and NOTICE are retained. Only tracked public source, connectors, tests and documentation images were imported. Production bindings, credentials, sessions, datasets and generated artifacts are not included.

Fagoo owns human Auth/MFA, users, units, contacts, provisioning and updates. The default Worker receives signed provider webhooks, connector traffic, public WhatsApp router links and existing scoped machine API credentials. It never accepts delegated identity headers or legacy human login/setup in managed mode. The `FagooCommunication` named entrypoint is exclusively a Service Binding target for the Fagoo API. It accepts canonical grants checked by PostgreSQL for every request. The reverse `FAGOO_AUTHORITY` binding rechecks current permission for asynchronous bot work, personal push and queue delivery.

`/v1/communication/units/:unitId/*` maps to the unit's adopted legacy profile. `communication_binding` must be reviewed before first access when adopting existing D1 data. New units default to their UUID as profile ID. No contacts are merged by phone. `contact-links` requires a visible canonical ERP contact and an explicitly chosen old contact; `contact-timeline/:uuid` returns only authorized conversation metadata.

Web configuration and operational screens are embedded React in `web/FagooCommunication.tsx`. The Fagoo controller supplies authenticated JSON/binary transport; no iframe, copied token, independent session or root React mount is used. CSS lives inside a ShadowRoot. Standalone users, contacts, installer and updater are excluded from navigation. Third-party application keys remain scoped and configurable from the same Fagoo surface. Internal chat is one-to-one text. Bot policies must declare every ERP resource and permission the specialist can use; authorization is the intersection of that policy, the person's role/restrictions and unit capabilities.

Mobile sends `X-Fagoo-Client: mobile`. That flag only restricts privileges: even administrators receive assigned conversations and minimal authorized claim previews; configuration APIs are unavailable. Panel/device tokens are rejected by the entire communication gateway. Personal pushes always use the restricted mobile scope. Ownership checks cover list/search/detail, messages, attachments, event streams and current delivery recipients. Transfers fence stale AI and revoke previous ownership immediately.

Queue notices use an internal `app:fagoo-queue:<unit>` identity, an explicitly selected number/pool, forced `free_only`, stable notice UUID receipts and a deadline. Pending acceptance is not reported as sent. PostgreSQL notice state is revalidated before enqueue and before actual delivery; unknown outcomes are status-reconciled, never blindly sent again. Removing Vinki commercial plans does not remove the WhatsApp window, quota or consent controls.

`fagoo_runtime(id=1,pause_outbound=1,updated=<milliseconds>)` pauses the coordinator's processing without rejecting inbound webhooks. It is not a transactional snapshot: wait for in-flight sends/runs to settle and back up D1 plus the R2 objects referenced by that snapshot. Keep MASTER_KEY separately. Old Wabotia code does not understand this flag, so first adoption requires the documented single-consumer cutover. The central Fagoo installer/updater owns deployment and migrations; this package exposes no deploy/setup/release scripts.

Validation: `npm ci`, `npm run check`, `npm test`, `node --test tests/gateway.test.mjs`, then the integrated ERP build. Tests run the inherited engine against real Miniflare D1/DO/R2 plus managed authorization regressions. No production deployment or device check is implied by these local checks.
